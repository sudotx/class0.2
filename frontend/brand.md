### Stack note

This project is **Vite + plain CSS**, not Next.js/Tailwind/shadcn — the shadcn 14-token scheme doesn't apply. Instead the palette was mapped directly onto the existing custom-property system already in `frontend/src/index.css`:

| Existing token | Mapped from |
|---|---|
| `--bg` | bg-base |
| `--bg-muted` | bg-elevated |
| `--text` | fg-base, lightened (muted body text) |
| `--text-h` | fg-base (headings, full contrast) |
| `--text-muted` | fg-base, lightened further |
| `--border` | bg-base ± 0.08L |
| `--accent` / `--accent-hover` | primary / primary+contrast step |
| `--error` / `--success` / `--warning` | kept semantically red/green/amber, hue-shifted to sit quietly next to the new blue |

Applied directly to `:root` and the `@media (prefers-color-scheme: dark)` block — no `.dark` class toggle exists in this codebase (it follows system preference only), so that's what got themed.

## Gradients

## Tone and voice

**Words to use:** measured, patient, quiet. Full sentences. Focus on the user's outcome ("your class is booked") not manufactured urgency.

**Words to avoid:** urgency language ("act now", "only 2 left!" unless literally true), exclamation marks, "simply"/"just"/"easy".

**Voice example:** "Your spot in Vinyasa Flow is booked. See you Saturday at 9."

## Usage dos and don'ts

**Do:**
- Use the `index.css` custom properties (`var(--accent)`, `var(--text)`, etc.) everywhere — never hardcode hex in component files.
- Test every screen in both light and dark (it's system-driven here, no manual toggle — check via OS appearance settings).

**Don't:**
- Hardcode colors in `.jsx` files or inline `style={{ color: '#...' }}`.
- Add a Tailwind/shadcn token layer on top of this — the project intentionally uses plain CSS variables.
